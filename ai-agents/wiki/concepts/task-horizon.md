# タスクホライズン（Task Horizon）

## 定義

AIシステムが50%の信頼性でこなせるタスクの所要時間の上限。METRが定義・測定しているAI能力の主要指標。タスクの複雑さ・長さをどこまでAIが担えるかを示す。

## 背景

AIが「役立つ」かどうかを測る既存のベンチマーク（正答率等）は、単一の問いに答えられるかを測るに過ぎず、複数ステップにわたる長時間タスクへの対応能力を反映しにくい。METRはこの課題に対し、「どれくらい長いタスクを自律的にこなせるか」という時間軸の指標を導入した。

## 詳細

### 測定方法

METRはAIシステムに様々な時間規模のタスクを与え、50%の確率で成功するタスクの所要時間を計測する（80%信頼度でも同様のトレンドが観測されている）。

### 実測値のトレンド

| モデル | 時期 | タスクホライズン |
|---|---|---|
| Claude Opus 3 | 2024年3月 | 約4分 |
| Claude Sonnet 3.7 | 2025年3月 | 約90分 |
| Claude Opus 4.6 | 2026年3月 | 約12時間 |
| Claude Mythos Preview | 2026年中頃 | 16時間以上（METRの測定上限に達した） |

- 2024年以前：倍増ペースは約7ヶ月ごと
- 2024年以降：倍増ペースが**約4ヶ月ごと**に加速
- この傾向が続けば、2026年内に「数日かかる作業」、2027年には「数週間かかる作業」が射程に入る

### タスクホライズンとハーネス設計の関係

タスクホライズンが長くなると、エージェントが長期的な文脈を保持し、方向性を自律的に修正するための[[harness-engineering]]がより重要になる。短いタスクで有効だったハーネスコンポーネントが冗長になる一方、長時間自律実行に特有の課題（方向漂流、コンテキスト肥大）への対策が必要になる。

[[context-anxiety]]は長時間タスクで顕著になるが、モデル能力の向上によって自然に緩和されるケースもある（Anthropic実験でOpus 4.6がコンテキストリセット不要になった事例）。

## 関連概念

- [[recursive-self-improvement]] — タスクホライズンの延長が最終的に到達する能力
- [[harness-engineering]] — 長時間タスクを支えるスキャフォールド設計
- [[context-anxiety]] — 長時間タスクでコンテキスト上限に近づいた際の早期終了現象
- [[agentic-development-loop]] — 長いタスクホライズンを前提とした開発ループ

## 代表的な実装・事例

- METR Time Horizons Benchmark — タスクホライズンの公式測定ベンチマーク
- SWE-bench — ソフトウェアエンジニアリングの能力を測定、2年で一桁%から飽和へ
- CORE-Bench — 既存研究の再現能力を測定、15ヶ月で20%から飽和へ
