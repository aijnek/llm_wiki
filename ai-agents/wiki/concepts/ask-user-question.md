# AskUserQuestion

## 定義

エージェントがユーザーに対して質問・確認・承認を求める際に使用する構造化インターフェース。通常のテキスト出力とは異なり、「これはユーザーへの質問である」というシグナルをツールコールとして明示的に発行する。

## 背景

チャット型エージェントでは、エージェントが質問を通常メッセージとして返し、ユーザーの次のメッセージをコンテキストに追加するだけで質問・回答サイクルが成立する。しかし[[ambient-agent]]のようなバックグラウンド動作型では、「どのテキスト出力がユーザーへの質問なのか」をアプリ側が判定する仕組みが必要になる。AskUserQuestionはその問題を構造化されたツールコールで解決する。

## 詳細

### エージェントタイプ別の価値

| エージェントタイプ | AskUserQuestionの価値 |
|---|---|
| チャット起点型 | 低〜中。マルチターン構造だけで十分。構造化したい場合に任意で使う |
| Ambient / イベントトリガー型 | 高。「ユーザーへのアクション要求イベント」として外部システムが検知・利用できる |

### 動作フロー（Ambient Agent文脈）

```
[Agent] バックグラウンド処理
    ↓ 判断が必要な条件を検出
[Agent] AskUserQuestion("この変更を適用してよいですか？") を発行
    ↓ ツールコールとして構造化
[App]  イベントを検知 → プッシュ通知/メール送信
    ↓ ユーザーが通知を受け取り、UIで回答
[Agent] 回答のみを受け取り処理を再開
```

### 通常テキスト返しとの違い

通常のテキスト返しでも「ユーザーへの質問」は実現できる。しかしAmbient Agent文脈では：

- 通常テキスト: アプリ側が「この出力は質問か、処理結果か」を自然言語解析で判定する必要がある
- AskUserQuestion: ツールコールの種類で自動的に識別できる。バックグラウンド処理とUI/通知レイヤーが疎結合になる

### ハーネス設計との関係

AskUserQuestionは[[harness-engineering]]における「振る舞いハーネス」の一形態として理解できる。エージェントの自律実行に人間の判断を組み込むための境界を明確に定義する仕組みである。
