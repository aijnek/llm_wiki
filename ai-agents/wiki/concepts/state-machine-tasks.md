# 状態遷移系タスク

## 定義

「ルールに従って状態を持ちながら判断を続ける」形式のタスク。現在の状態に基づいて条件分岐し、状態を更新しながらループを継続する。終了条件が複数あったり、遅延判定（仮→確定/降格）を含む場合は複雑度がさらに高まる。

## 背景

LLMにとって状態を持つタスクは難しい、というのが直感的な認識だったが、実際には自己回帰的な出力という特性が状態遷移系タスクと相性がいいことが観察されている。問題になるのは「状態そのものの保持」より「長距離依存の追跡能力」であることが分かってきた。

## 詳細

### 自己回帰モデルとの親和性

状態遷移系タスクでは、過去の出力にすべての必要情報が残っている。LLMは自己回帰的に過去のコンテキスト全体を参照しながら次のトークンを生成するため、「状態をメモリに保持する」という明示的なアーキテクチャを必要とせず、コンテキスト内の過去出力から状態を読み取ることができる。

この特性により、「ルールに従い判断を継続する系」はLLMと本質的に親和性が高い。

### 長距離依存とモデルサイズの関係

問題になるのは、ルールが複雑になるにつれて「コンテキスト内の遠い箇所にある状態情報」を正確に追跡する能力が要求されることだ。この長距離依存の追跡キャパシティはモデルサイズと相関する。

7タスク×6モデルの観察では:
- 単純な繰り返し（Task 1）: 4Bモデルでも対応可能
- 条件付き終了（Task 2-3）: 27B相当が必要
- 複数の条件分岐+遅延判定（Task 4-6）: Sonnet 4.6クラスが必要
- 動的ルール変化+複数終了条件（Task 7）: Opus 4.7が必要

### 状態の明示出力によるハーネス補完

各ステップで現在の状態を明示的にテキスト出力させる指示を与えると、小さなモデルでも長距離依存の問題を軽減できる。状態が常にコンテキストの直近に存在することになるため、遠い情報を参照する必要がなくなる。

Sonnet 4.6はTask 6（状態出力指示を削除）でも自発的に状態を出力してカバーした。これは高能力モデルが「何を出力すれば自分が正確に追跡できるか」を内的に判断していることを示唆する。
