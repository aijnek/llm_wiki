# AGENTS.md

## 定義

AIコーディングエージェントに対してリポジトリの操作方法・規則・構造を伝えるための指示ファイル。リポジトリのルートまたは各ディレクトリに配置し、エージェントの実行時にコンテキストに挿入される。

## 背景

AIコーディングエージェントがリポジトリを操作する際、どのような規則や慣習に従うべきかを伝える手段が必要となった。当初は「1つの大きなAGENTS.md」に全情報を詰め込むアプローチが取られたが、複数の問題が判明した。

## 詳細

### 「大きなAGENTS.md」の失敗パターン

1. **コンテキストの圧迫**: 巨大な指示ファイルがタスクやコード・関連ドキュメントを押しのけ、エージェントが重要な制約を見落とす
2. **過度なガイダンスによる指針喪失**: すべてが「重要」と書かれていると何も重要でなくなり、エージェントは意図的にナビゲートせず局所的なパターンマッチングに終始する
3. **マニュアルの腐敗**: 分厚いマニュアルは古びた規則の墓場となり、エージェントは真偽を見極められない
4. **機械的検証の困難さ**: 単一の塊はカバレッジ・鮮度・オーナーシップのチェックに向かない

### 推奨アプローチ: 目次としてのAGENTS.md

AGENTS.mdを「百科事典」ではなく「目次」として扱う。

- **長さの目安**: 約100行
- **役割**: 主にマップとして機能し、より深い信頼性のある情報源への指針を提示する
- **構造化されたdocs/ディレクトリ**: リポジトリの知識ベースを`docs/`に分散配置し、AGENTS.mdはそこへの参照を持つ

### docs/ディレクトリの構成例（OpenAI実践より）

```
AGENTS.md           ← 約100行の目次
ARCHITECTURE.md     ← ドメイン・パッケージのトップレベルマップ
docs/
├── design-docs/    ← 設計ドキュメント（検証ステータス付き）
├── exec-plans/     ← 実行プラン（active/completed/tech-debt）
├── generated/      ← 自動生成ドキュメント（DBスキーマ等）
├── product-specs/  ← 製品仕様
└── references/     ← 外部ライブラリのLLMs.txt等
```

### 段階的開示の原則

エージェントは小さく安定した入口から始め、必要に応じて詳細情報にアクセスする。最初から膨大な情報に圧倒されることなく、「次にどこを見るべきか」を学習できる構造が望ましい。

### 鮮度の維持

専用のリンターとCIジョブでナレッジベースが最新・相互参照・適切構造であることを検証する。定期実行の「ドキュメント整備エージェント」が陳腐化したドキュメントをスキャンし、修正PRを作成する。
