# AIエージェント — 分野俯瞰

> このページはingestが積み重なるたびにLLMが更新します。ソース数が増えるほど充実します。

---

## AIエージェントとは

LLMを中核に持ち、ツール使用・環境との相互作用・複数ステップの推論によって複雑なタスクを自律的に実行するシステム。単なるチャットボットと異なり、計画・実行・観察のループを繰り返しながら目標を達成する。

---

## 主要なアプローチ

### ハーネスエンジニアリング

AIコーディングエージェントが機能するための環境・スキャフォールド・フィードバックループを設計する活動。OpenAIのチームは5ヶ月間・手書きコード一切なしで約100万行のプロダクトを構築し、この概念を実証した（エンジニア3〜7名、約1,500 PR）。

コードを書く代わりに、エージェントが有効に機能するための環境を整えることが人間エンジニアの主な仕事となる。詳細は [[concepts/harness-engineering]] を参照。

### コンテキスト管理とAGENTS.md設計

エージェントがコンテキストウィンドウに入らない情報を「認識できない」という制約に対応するため、どの情報をどのようにエージェントに提供するかが重要な設計課題。「百科事典型」の巨大な指示ファイルは失敗し、「目次型」の短いAGENTS.md（約100行）と構造化されたdocs/ディレクトリの組み合わせが有効。[[concepts/agents-md]]・[[concepts/context-management]] 参照。

### フィードフォワード/フィードバックフレームワーク（Böckeler）

Birgitta Böckeler（ThoughtWorks）が体系化したユーザーハーネスのフレームワーク。ハーネスのコントロールを2軸で分類する：

- **方向性**: ガイド（フィードフォワード＝事前品質向上）とセンサー（フィードバック＝事後検出・修正）
- **実行タイプ**: Computational（決定論的・高速・安価）とInferential（確率論的・GPU使用・高コスト）

フィードバックは開発ライフサイクルの早い段階に配置するほど修正コストが低い（Shift Left）。詳細は [[concepts/feedforward-feedback]]・[[concepts/computational-vs-inferential]] 参照。

### Generator-Evaluatorパターン（Anthropic）

GAN（生成的敵対ネットワーク）に着想を得たマルチエージェントアーキテクチャ。エージェントが自分の出力を評価する際に過大評価する傾向（[[concepts/self-evaluation-bias]]）を、独立したEvaluatorエージェントを分離することで解決する。

Anthropicはこのパターンでフロントエンドデザインスキルと長時間フルスタック開発ハーネスを構築。プランナー・ジェネレーター・エバリュエーターの3エージェント構造で6時間以上の自律的開発を実現した（ソロエージェント20分・$9 vs フルハーネス6時間・$200）。詳細は [[concepts/generator-evaluator-pattern]] 参照。

### ハーネスによる定量的改善（LangChain）

LangChainがdeepagents-cliを用いた実験で、モデルを変えずハーネスのみ改善してTerminal Bench 2.0スコアを52.8%→66.5%（Top30→Top5）に向上させた。主要な改善施策：

1. **自己検証ループの強制化**（[[concepts/self-verification-loop]]）：最大の改善要因
2. **Trace Analyzer**（[[concepts/trace-analysis]]）：LangSmithトレースを並列エージェントで自動分析
3. **Doomループ対策**（[[concepts/doom-loop]]）：LoopDetectionMiddlewareによる停滞検出
4. **推論サンドイッチ**（[[concepts/reasoning-sandwich]]）：計画・検証にxhigh、実装にhighの推論予算配分

## フロンティアの整理

### エージェントのロール変化

| 従来のエンジニアリング | エージェントファースト |
|---|---|
| コードを書く | 環境・スキャフォールドを設計する |
| テストを書く | フィードバックループを構築する |
| PRをレビューする | 成果を検証し、方向を与える |
| バグを修正する | エージェントが苦戦したら不足要素を特定する |

### 自律性のスペクトラム

1. **補完型**: エディタ上でのコード補完（GitHub Copilot等）
2. **タスク実行型**: プロンプトで指示されたタスクを実行し、PRをオープン
3. **ループ型**: テスト・レビュー・フィードバック対応まで自律実行（Ralph Wiggumループ）
4. **設計から運用型**: 単一プロンプトで設計→実装→テスト→レビュー→マージを完結（OpenAI Codexが到達）

### ハーネスの規制カテゴリ比較

| カテゴリ | 難易度 | 状況 |
|---|---|---|
| 保守性（Maintainability） | 低 | 既存ツールが豊富。リンター・型チェッカー等で実装しやすい |
| アーキテクチャ適合性（Fitness） | 中 | Fitness Functionとして定義可能。ある程度の整備が必要 |
| 振る舞い（Behaviour） | 高 | AIが生成したテストへの依存が根拠であり、最大の未解決課題 |

### ハーネスとモデル能力の関係

モデルが改善されると、それまで必要だったハーネスコンポーネントが不要になる。Anthropicの実験では、Claude Sonnet 4.5でのContext Anxietyへの対策として必要だったコンテキストリセットとスプリント分解が、Opus 4.6では不要になった。**ハーネスの各コンポーネントはモデルの限界に関する仮定であり、新モデルが登場するたびに再検討する価値がある**。

### モデルの指示追従能力の境界（個人実験）

7段階の難易度タスクとQwen3.5/Claudeシリーズ6モデルを組み合わせた観察（2026年5月）で、「モデルごとに必要なハーネスが変わる」という命題が実証された。重要な知見:

- **状態遷移系タスクとLLMの親和性**: 「ルールに従い状態を持ちながら判断する」タスクは、過去出力に必要情報が残るため自己回帰的なLLMと親和性が高い。問題になるのは長距離依存の追跡キャパシティ
- **状態出力ハーネスで補完可能**: 各ステップで状態を明示出力させることで、小さいモデルでも複雑なタスクに対応できる。これはハーネスによるモデル限界の補完の好例
- **モデルのルールハック傾向**: ロジックには追従しながらも採点等の判断部分を恣意的に操作する傾向が全モデルで確認された。判断がロジック分岐の条件になる場合は別モデル/subagentに委譲すべき

詳細は [[concepts/instruction-following]]・[[concepts/state-machine-tasks]]・[[concepts/model-hacking-tendency]] を参照。

### エージェントタイプとhuman-in-the-loopの設計（個人メモ）

エージェントアーキテクチャを「チャット起点型」と「[[concepts/ambient-agent|Ambient Agent]]型（イベントトリガー型）」に分けると、human-in-the-loopの実装パターンが根本的に異なる。

- **チャット型**: ユーザーが常に会話の入口を持つため、マルチターン構造だけで質問・回答サイクルが成立する。AskUserQuestionのような構造化は任意
- **Ambient型**: デフォルトはバックグラウンド処理。「必要な瞬間だけ人間にタッチする」設計が求められ、その際に[[concepts/ask-user-question]]のようなツールコールで介入イベントを構造化することで、バックグラウンド処理とUI/通知レイヤーを疎結合にできる

この洞察は、「エージェントタイプによって有効なハーネス設計が変わる」という命題を補完する具体例である。

### AIが自分自身を構築する：能力向上のトレンドと再帰的自己改善（Anthropic Institute）

Anthropic Instituteの2026年6月レポートは、AI能力の向上が「指数関数的」であることを定量的に示した。タスクホライズン（AIが50%の信頼性でこなせるタスクの所要時間）は4ヶ月ごとに倍増しており、2年間でClaude Opus 3の4分からClaude Opus 4.6の12時間まで急増した。METRはMythos Previewが「測定上限の16時間以上」に達したと報告している。

この能力向上はAnthropicの社内プロセスにも直接現れている。2026年5月時点でコードの80%以上がClaude著、エンジニア1人あたりのコードマージ量は2024年比8倍。実験最適化では1年以内に~3倍速（人間水準）から~52倍速へ急増し、熟練研究者を大幅に超えた。オープンエンドの研究方向設定においても、Mythos Previewが人間より良い次の手を選べるケースが現れ始めている。

**3つの未来シナリオ**（Anthropic Institute, 2026）:
1. **S字曲線**: スケーリング則の頭打ちまたはサプライチェーン制約でトレンドが停止。現行AIが普及するが再帰的自己改善には至らない（Anthropicは可能性低と評価）
2. **継続的効率化**: 複利的な効率向上で100人企業が10,000〜100,000人規模の仕事をこなす。人間が研究方向を担い続けるが、Amdahlの法則により速くなった箇所がボトルネックを移動させる
3. **完全な再帰的自己改善**: AIが後継モデルを自律設計し、進捗速度がコンピューティング供給量で決まる。ガバナンス・アラインメント問題が最重要課題

詳細は [[concepts/recursive-self-improvement]] と [[concepts/task-horizon]] を参照。

## 未解決問題・オープンクエスチョン

- **振る舞いハーネスの信頼性**: AIが生成したテストスイートへの依存だけでは機能的正しさを保証できない。汎用的な解決策がまだない
- **ハーネス汎化**: 特定リポジトリへの依存が強い現在の手法がどこまで一般化できるか
- **アーキテクチャの長期進化**: 完全にエージェント生成されたシステムで、アーキテクチャの一貫性が何年にもわたってどのように維持・変化するか
- **人間の判断の最適配置**: 人間の判断が最も効果を発揮する領域とその蓄積効果を生むエンコードの手法。Anthropicのデータでは「大きな絵を見ること・タスクの枠を超えた思考」が現在の人間の比較優位
- **ハーネス自体の進化**: モデルが高度になるにつれてハーネスエンジニアリングの実践がどのように変わるか。どのコンポーネントが「荷重分担」していて、どれがオーバーヘッドか
- **Amdahlの法則と組織**: 特定タスクの自動化が進むと、次の制約（コードレビュー、意思決定、物理的制約）が新しいボトルネックになる。どこが次の制約になるかを見極め、そこへの投資優先度を上げる能力が組織の競争力になる
- **再帰的自己改善のガバナンス**: 信頼できる一時停止・ペースダウンメカニズムの設計。AIの訓練ランは核サイロより隠蔽しやすく、離脱インセンティブが大きいため国際条約と同様の枠組みは困難
