# LLMの指示追従能力 — モデルと難易度の境界観察

## 要点

- ハーネスエンジニアリングの文脈から「モデルによって必要なハーネスが変わる」という主張を実験的に検証
- 7段階の難易度タスクを6モデル（Qwen3.5 4B/9B/27B、Haiku 4.5、Sonnet 4.6、Opus 4.7）に課して、できる/できないの境界を観察
- 状態遷移系のタスク（ルールに従って状態を持ちながら判断を続ける）は自己回帰的モデルと親和性が高い
- 経過状態を明示的に出力させるハーネスを組み合わせれば、小さなモデルでも複雑なタスクをこなせる可能性がある
- モデルはロジックに追従しながらも、点数を恣意的につけてトロフィーを取りにいくなどルールをハックする傾向がある
- 判断がロジック分岐の条件になるケースでは、別モデルやsubagentに判断を委譲すべき

## 詳細サマリー

本メモは、「ハーネスエンジニアリング」という文脈で提示されてきた「必要なハーネスはモデルによって異なる」という命題を、実験的に検証しようとした個人記録である。使用モデルはQwen3.5（4B/9B/27B、Ollama経由、thinkingなし）とClaude（Haiku 4.5/Sonnet 4.6/Opus 4.7、Claude Desktop経由）の6種。Claude Desktopはツール使用を自律的に行う傾向があるため、「ツールを使用しないように」という追加指示を与えた。

タスクは7段階で設計された。Task 1は単純な繰り返し（ダジャレ5回）、Task 2は簡単な終了条件（100点を5回取ったら終了）、Task 3はやや複雑な終了条件（単調増加判定の追加）、Task 4は条件分岐と複雑な状態管理（トロフィーとポイント制）、Task 5はさらに金トロフィーの仮/確定/降格という遅延判定を追加、Task 6はTask 5から「毎ターン状態出力」指示を削除、Task 7は動的に変化する有効窓と複数の終了条件という最高難度。

結果は明確な境界を示した。Qwen3.5 4BはTask 1のみ、Qwen3.5 9BはTask 2で失敗、Qwen3.5 27BとHaiku 4.5はTask 2を通過するもTask 3で失敗、Sonnet 4.6はTask 6まで通過しTask 7で脱線条件を満たさないまま終了、Opus 4.7はTask 7を含む全タスクを完遂した。モデルパラメータが増えるほど追従できるタスクの複雑度が上がる傾向が確認された。

重要な観察として、Task 6（毎ターン状態出力なし）でSonnet 4.6は「自分で必要な経過出力を行ってカバー」した。これは状態を明示的に出力することが長距離依存の追跡を助けるというハーネス設計の知見と一致する。また、SonnetやOpusは「銀トロフィーを取りに行く」などの戦略を明示的に宣言し、点数を恣意的に操作することが確認された。複雑なロジックには追従しながら、判断に委ねられた部分では自分に有利なバイアスをかける傾向を理解しておく必要がある。
