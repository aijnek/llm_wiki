# エージェントタイプによってAskUserQuestionの価値は異なる

## 要点

- チャット起点エージェントではAskUserQuestionの価値は限定的。マルチターン構造だけで質問・回答のループが完結するため
- Ambient Agent（イベントトリガー型）では、「デフォルトはバックグラウンド処理」「必要な瞬間だけ人間に触れる」という設計が求められる
- AskUserQuestionはその際に「ユーザーへのアクション要求」を構造化されたイベントとして明示するインターフェースとして機能する
- バックエンドがAskUserQuestionを検知して通知（プッシュ/メール/バッジ）を送り、回答を再開トリガーとして渡す「イベント駆動のhuman-in-the-loop」が実現できる
- 通常テキスト返しと比べ、「どの出力がユーザーへの質問か」の判定が不要になり、バックグラウンド処理とUI/通知レイヤーを疎結合にできる

## 詳細サマリー

AIエージェントは大別して「チャット起点型」と「Ambient/イベントトリガー型」の2種類に分けられる。チャット起点型はユーザーが常に会話コンテキストの入口を握っており、エージェントが質問を通常メッセージとして返し、ユーザーの次のメッセージをそのままコンテキストに追加するマルチターン構造だけで十分機能する。この場合、AskUserQuestionのような特別なインターフェースを使わなくても質問・回答のサイクルは成立する。

Ambient Agent（イベントトリガー型）は、ユーザーが意識を向けていないタイミングにバックグラウンドで処理を進め、特定条件を満たした瞬間だけ人間の判断を求める設計が基本となる。この「アイドル状態→ピンポイントで人間にタッチする」動きにおいて、AskUserQuestionは非常に相性が良い。ツールコールとして質問意図が明示されるため、アプリ側が検知して通知を飛ばし、ユーザーの回答をイベントとしてエージェントの続きに渡す「イベント駆動のhuman-in-the-loop」フローを疎結合に構築できる。

この洞察は、エージェントのアーキテクチャタイプによってハーネスの設計パターンが変わるという命題の具体例でもある。チャット型では人間との対話がデフォルトであるため構造化の必要性が低いが、Ambient型では人間への介入が例外的イベントであるため、その「例外」を構造的に表現するインターフェースが重要になる。
