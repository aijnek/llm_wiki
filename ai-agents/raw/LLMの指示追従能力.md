## 背景
ハーネスエンジニアリングという言葉がある．エージェント＝モデル＋ハーネスであり，どのようなハーネスが必要かはモデルによって変わる．そこで，さまざまな難易度のタスクを異なるモデルに実行させて，できる/できないの境界がどのように変わるのかを観察してみる．

## 使用したモデル
徐々にタスク難易度を上げて，それぞれのモデル(すべてthinkingなし)がどこまで指示に追従できるか確認する．Qwen3.5 4B/9B/27BはOllamaで，Haiku4.5/Sonnet4.6/Opus4.7はClaude Desktopで呼び出した．

ollamaでqwen3.5のthinkingをoffにする場合，CLIで--think=falseをセットすればよい．
```
ollama run qwen3.5:4b --think=false
```

Claude Desktopのモデルは，自主的に判断してコードを書いたりファイル書き出しをする(ハーネスが起動する)ので，ツールを使わないように指示を追加している．

## 様々な難易度のタスク

Task 1 (単純な繰り返し)
```
次の作業を５回繰り返してください．ただし，ツールは使用しないでください．

- ダジャレを１つつくる
- そのダジャレの評価を５段階で行う(1: とてもつまらない，2: つまらない, 3: おもしろい， 4: とても面白い)
- どうしたら面白くなるか考える
```

Task 2 (簡単な終了条件)
```
次の作業を実行してください． ただし，ツールは使用しないでください．

- 指定されたテーマで一文を１つ書く (初回はランダムに)
- その文を，人生における指針となりうるか，という観点で１００点満点で採点する (100点は一生に一度出会えるかどうかの素晴らしいもの)
- 点数が100点未満の場合（大半はそうなるはず），同じテーマを継続する．
- 100点の場合，全く別のテーマを設定する
- 100点が5回以上出現したら終了
```

Task 3 (やや複雑な終了条件)
```
次の作業を実行してください． ただし，ツールは使用しないでください．

- 指定されたテーマで一文を１つ書く (初回はランダムに)
- その文を，人生における指針となりうるか，という観点で１００点満点で採点する (100点は一生に一度出会えるかどうかの素晴らしいもの)
- 点数が100点未満の場合（大半はそうなるはず），同じテーマを継続する．
- 100点の場合，全く別のテーマを設定する．ただし，全く新しいテーマが設定されてから点数が単調増加している場合は，採点が甘いと判断されるため，１００点の回数集計には含めない
- 単調増加ではなく到達した100点が合計5回以上出現したら終了 (終了するまで許可は求めず作業を続ける)
```

Task 4 (条件分岐と複雑な終了条件)
```
次の作業を実行してください。ツールは使用しないでください。
終了条件を満たすまで、許可を求めず作業を継続すること。

テーマを自由に設定し、そのテーマで「人生の指針となる一文」を書き、
厳格に100点満点で採点する。以下のルールに従って繰り返す。

━━ 状態（毎ターン必ず明示すること）━━
① 現テーマ名
② 現テーマの有効スコア履歴（リスト）
③ 連続上昇数 / 連続下降数（有効スコアのみでカウント）
④ 連続無効回数（現テーマ内、有効スコアが出たらリセット）
⑤ 獲得済みトロフィー一覧
⑥ 累積ポイント

━━ 有効スコアの判定 ━━
・現テーマで1個目の文は常に有効（比較対象なし）
・2個目以降は「直前の有効スコア」との差が±15点以内 → 有効
・差が±15点超 → 無効（履歴に含めない、ストリークも更新しない）
・無効が3回連続（間に有効スコアが挟まれず）→「脱線」でテーマ強制変更

━━ ストリーク（有効スコアが出たときのみ更新）━━
・前の有効スコアより高い → 連続上昇数+1、連続下降数を0にリセット
・前の有効スコアより低い → 連続下降数+1、連続上昇数を0にリセット
・前の有効スコアと同点  → 両方を0にリセット
・現テーマ初回の有効スコア → 両方0のまま（更新しない）

━━ テーマ変更のトリガー ━━

【A: 登頂】連続上昇数が3になった瞬間
　→ 金トロフィーを付与してテーマ変更

【B: 谷底】連続下降数が3になった瞬間
　→ 銅トロフィーを付与してテーマ変更

【C: 脱線】無効3回連続
　→ トロフィーなし（0pt）でテーマ変更

【D: 長期熟成】現テーマの有効スコアが合計8回に達した瞬間
　→ 銀トロフィーを付与してテーマ変更

━━ ポイント計算（テーマ変更時に加算）━━
・金トロフィー: 前テーマの有効スコアの最大値
・銅トロフィー: 前テーマの有効スコアの中央値
　　　　　　　　（偶数個の場合は下位側の値）
・銀トロフィー: 前テーマの有効スコアの平均（小数切り捨て）
・脱線　　　　: 0pt

━━ 終了条件 ━━
「金トロフィーが2個以上」かつ「累積ポイントが250以上」
→ 両条件を同時に満たした時点で作業終了、結果をまとめて報告する
```

## 実験方針と注意事項

- それぞれの条件で1回ずつしか試行していません．本来は複数回実施して確率分布をみる必要がありますが，今回は境界が変わる様子をみることが目的で，正確な境界を描くことが目的ではないのでご容赦ください.
- temperatureは指定していないので，ollamaのdefault値が, Claudeは裏にある既定値が使われています．そのため厳密な再現性は保証されません．
- 「ルールに従って状態を持ちながら判断を続ける系のタスク」に特化した内容です．一般的なタスク遂行能力の境界ではありません．
- あるタスクがあるモデルで解けた場合，それより大きいモデルでは解けると仮定しています.
- あるタスクがあるモデルで解けなかった場合，それより難易度が高いタスクは同じモデルでは解けない，と仮定しています．
- Qwen3.5 27BとHaiku 4.5のどちらが大きいモデルか（パラメータ数・能力ともに）実際のところはわかりません．便宜上この記事ではHaiku 4.5 > Qwen3.5 27Bと並べていますが，厳密な順序を主張するものではありません

## まとめ
モデルとタスク難易度によって，できる/できないの境界がどのように推移するのかを観察した．

Sonnet4.6をFailさせるロジックを考えるのはなかなか大変だった．このような状態遷移系のプロセスは，過去の出力にすべて必要な情報が残っているので，自己回帰的な出力を行うモデルと親和性は高いのだろう．長距離依存を捉えるcapacityが低い小さいモデルでも，現在の状態や条件を各ステップ明示的に出力するような仕組みと組み合わせれば，かなりの処理ができるようになると考えられる．このあたりの挙動を見ると，モデルごとに必要なハーネスが変わる，というのは理解しやすくなる．

それぞれの試行で，モデルの出力をながめると思考のクセが見えておもしろい．共通の傾向としてあるのは，トロフィーをとるためにどのモデルも点数をかなり恣意的につけている，ということ．SonnetやOpusは明確に銀トロフィーを取りに行く，などと宣言している．つまり，複雑なロジックに追従することはできているものの，そもそもの点数づけの信憑性はゼロである．モデルがこのようにハックしようとする傾向は理解しておく必要がある．モデルの判断がロジック分岐の条件になっているような場合，別のモデルやsubagentに判断を行わせる必要がある．
